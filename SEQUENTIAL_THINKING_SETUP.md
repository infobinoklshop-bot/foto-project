## Зачем нужен для вашего проекта

Sequential Thinking помогает **систематически** решать сложные многоэтапные задачи, разбивая их на логические шаги.

### Идеально подходит для:

#### 1. **Архитектурное планирование**
```
Задача: Добавить новый модуль для парсинга поставщика

Sequential Thinking разобьет на шаги:
1. Анализ требований (какие данные нужны)
2. Проектирование интерфейса (какие функции)
3. Планирование обработки ошибок
4. Интеграция с существующим кодом
5. Тестирование
```

#### 2. **Отладка сложных проблем**
```
Проблема: Дубликаты товаров создаются при импорте

Sequential Thinking:
1. Проанализирует как работает checkProductDuplicate()
2. Найдет где логика ломается
3. Предложит тесты для воспроизведения
4. Спланирует исправление
5. Проверит side effects
```

#### 3. **Рефакторинг**
```
Задача: Улучшить 05_supplier_parsing.gs.js

Sequential Thinking:
1. Анализ текущей структуры
2. Выявление проблемных мест
3. Планирование изменений
4. Порядок рефакторинга
5. Проверка совместимости
```

#### 4. **Принятие технических решений**
```
Вопрос: Использовать Playwright или UrlFetchApp для нового парсера?

Sequential Thinking:
1. Анализ требований (динамический контент?)
2. Оценка сложности (JavaScript на странице?)
3. Сравнение производительности
4. Оценка стоимости поддержки
5. Финальная рекомендация
```

Используй Sequential Thinking для планирования:
Как добавить кэширование для InSales API запросов?

### Автоматическое использование
Я буду автоматически использовать Sequential Thinking когда вижу:
- Слова: "спланируй", "архитектура", "дизайн системы"
- Сложные многоэтапные задачи
- Запросы на принятие решений
- Отладку комплексных проблем

## Примеры для вашего проекта

### Пример 1: Планирование нового функционала
```
Спланируй добавление функции автоматического определения категории товара
на основе его характеристик
```

**Что произойдет:**
1. Анализ структуры данных (какие характеристики есть)
2. Изучение категорий InSales
3. Алгоритм маппинга (правила определения)
4. Обработка edge cases
5. Интеграция в существующий код
6. План тестирования

### Пример 2: Решение архитектурной проблемы
```
У меня 3 AI assistants в 07_description_ai.js.
Как оптимизировать workflow чтобы использовать меньше API вызовов?
```

**Что произойдет:**
1. Анализ текущего pipeline (COPIER → CRITIC → EDITOR)
2. Выявление дублирующихся вызовов
3. Варианты оптимизации
4. Оценка качества результата
5. Выбор оптимального решения
6. План миграции

### Пример 3: Отладка багов
```
Товары с одинаковым артикулом создаются как разные.
Найди проблему пошагово
```

**Что произойдет:**
1. Анализ функции checkProductDuplicate()
2. Проверка алгоритма сравнения
3. Тестирование с реальными данными
4. Выявление условия когда баг возникает
5. Исправление + тесты

## Когда НЕ использовать

❌ **Простые задачи:**
```
"Добавь комментарий к функции"
"Исправь опечатку"
```

❌ **Очевидные решения:**
```
"Как прочитать файл?"
"Где найти документацию?"
```

## Сравнение с обычным подходом

### Без Sequential Thinking:
```
User: Добавь rate limiting для InSales API

Claude: Вот код:
function rateLimiter() {
  // ... сразу предлагает решение
}
```

**Проблема:** Может не учесть все edge cases

### С Sequential Thinking:
```
User: Добавь rate limiting для InSales API

Claude с Sequential Thinking:
1. Анализирую текущие лимиты InSales API
2. Изучаю существующие запросы в коде
3. Планирую где применить rate limiting
4. Проектирую механизм (token bucket? leaky bucket?)
5. Обрабатываю retry logic
6. Предлагаю финальное решение с тестами
```

**Результат:** Комплексное решение, которое точно работает
